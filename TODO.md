## Состояние после v0.1.1

Опубликован [v0.1.1](https://github.com/Hecatoncheir/amnezia-proxy-manager/releases/tag/v0.1.1),
коммит `60fa290`. [CI](https://github.com/Hecatoncheir/amnezia-proxy-manager/actions/runs/39145193355)
и [выпуск](https://github.com/Hecatoncheir/amnezia-proxy-manager/actions/runs/39145193387)
успешны на трёх ОС. Есть Setup/DMG/RUN, переносимые архивы, SHA-256, обновление
Windows через интерфейс, общая иконка и сохранение положения окна.

Целевой сценарий: UI поставляется отдельно от настоящего backend
`bropines/awg-wireproxy` v2.1.0. При запуске UI проверяет локальный движок и последние
совместимые выпуски в репозитории backend, предлагает загрузку, проверяет пакет
и активирует его. Само скачивание не включает VPN: импорт M2 реализован, управление процессом и кнопка подключения реализованы в M3 и проверены на Windows.
Небольшой собственный `proxy-engine` — supervisor, а не AmneziaWG backend.

## M3 — Управление процессами и IPC

Основной сценарий реализован и проверен на Windows. Подробности: [управление сессией](docs/SESSION.md).

- [x] JSON Lines v1 через stdin/stdout: hello, capabilities, requestId, start/stop/status и события состояния.
- [x] Ограничения строки 512 КиБ/конфига 64 КиБ, ответов UI 8 КиБ, таймауты и согласование версии; конфиг не попадает в аргументы и диагностику.
- [x] Выбор backend по активному профилю, повторная проверка SHA-256, Go module/OS/CPU и абсолютного пути без shell.
- [x] Запуск AmneziaWG через --config/--silent и Xray через run -config; собственные SOCKS5/HTTP только 127.0.0.1:1080/8080.
- [x] Отмена запуска, start/stop/status, безопасные ошибки, наблюдение за аварийным выходом и повторное подключение.
- [x] Защищённый временный каталог ACL/0700 и файл 0600 на всё время сессии, удаление после остановки; marker + lock для уборки после аварии при следующем запуске supervisor.
- [x] Проверка обоих занятых портов, двойного start, повторного stop, отмены во время подготовки; запрет смены/удаления профиля во время сессии.
- [x] Остановка при закрытии UI/EOF; Windows Job Object для supervisor и приостановленного до назначения в Job дочернего процесса.
- [x] Unix: группы процессов, SIGTERM с ограниченным ожиданием и SIGKILL; Linux parent-death signal. Нативное исполнение Unix ещё требует проверки.
- [x] Раздельные состояния: процесс запускается → SOCKS5/HTTP готовы → HTTPS подтверждён либо сеть не подтверждена; прямого fallback нет.
- [x] 100 циклов start/stop с настоящими дочерними тестовыми процессами на Windows: без оставшихся портов и временных конфигов.
- [x] Проверка EOF, принудительной гибели supervisor/дочернего процесса, неверного хеша, oversized IPC и версии протокола; повторный запуск после сбоя.
- [x] Нативно: реальный Xray + выбранный обновлённый профиль → HTTPS через SOCKS5 → stop → повторное подключение; реальный AWG + синтетический профиль → listeners → close; порты освобождены.
- [ ] Проверить реальную AWG-сеть с пользовательским профилем; текущая проверка AWG не подтверждает VPN-трафик.
- [ ] Нативные циклы, EOF, сигналы и аварии на Linux/macOS; отдельно закрыть риск SIGKILL supervisor на macOS без parent-death signal.

Критерий выхода Windows выполнен для управления процессами. Полная готовность трёх ОС требует нативных испытаний; сетевые сценарии и DNS-утечки относятся также к M5.
