# Весь трафик через VPN и блокировка при обрыве

Добавлено в v0.1.15 от 2026-10-21. Поддерживаемые цели: Windows x64, Linux x64 и macOS arm64 (Apple Silicon). Переключатель доступен на всех трёх ОС; локальные прокси сохраняются.

## Использование

На главном экране или в **Настройки → Общие** включите **«Пропускать весь трафик через VPN»**. Выбранный профиль AmneziaWG/VLESS используется и для системного трафика, и для локальных прокси. Порты SOCKS5/HTTP сохраняются. При первом подключении автоматически загружается отдельный sing-box; проверяются SHA-256 архива и исполняемого файла.

| ОС | Запрос прав | Сетевой фильтр | Имя TUN |
| --- | --- | --- | --- |
| Windows x64 | UAC для вспомогательного процесса | WFP | `AmneziaProxyVPN` |
| Linux x64 | `pkexec` и графический агент polkit | Отдельная таблица nftables | `apm-vpn` |
| macOS arm64 | Системный диалог через `osascript` | Отдельный anchor PF | `utun233` |

В Linux установите `nftables`, `pkexec` и графический агент polkit вашего рабочего стола; ядро должно предоставлять `/dev/net/tun`. Приложение не включает службу nftables и не переписывает `/etc/nftables.conf`. В macOS используется системный PF: в корневом наборе правил должен присутствовать стандартный `anchor "com.apple/*"`. Ранние сторонние `pass quick`, anchors перед нашим и `skip` для внешних интерфейсов отклоняются. Приложение не заменяет `/etc/pf.conf` и чужие наборы правил.

**«Блокировать интернет при обрыве VPN»** включено по умолчанию. Эта настройка действует только в режиме всего трафика. При отказе запуска защиты VPN не переходит к обычному подключению. При аварии VPN/TUN или потере IPC защитные правила остаются в системе. Автоматическое переподключение их сохраняет. Ручное отключение снимает правила после завершения сетевых процессов. Изменять режим можно после отключения.

После сбоя приложения используйте **«Снять блокировку интернета»**. Действие отменяет автоматические повторы и запрашивает повышенные права при необходимости. При отказе в авторизации блокировка может сохраниться. Правила не устанавливаются в загрузочную конфигурацию ОС; защита до входа пользователя и запуска приложения не обеспечивается.

Запасной способ восстановления из PowerShell, запущенного от имени администратора, в каталоге приложения:

```powershell
.\proxy-engine.exe --unblock-vpn
```

Команда удаляет только правила Amnezia Proxy Manager. Она не выключает Windows Firewall и не меняет чужие правила.

Для Linux и macOS выполните из терминала с фактическим путём установленного компонента:

```sh
# Linux: компонент рядом с приложением в ~/.local/opt/amnezia-proxy-manager/
sudo ~/.local/opt/amnezia-proxy-manager/proxy-engine --unblock-vpn
# macOS
sudo /Applications/amnezia_proxy_manager.app/Contents/MacOS/proxy-engine --unblock-vpn
```

Linux-команда удаляет только таблицу `inet amnezia_proxy_vpn`. macOS очищает только `com.apple/000.amnezia-proxy-manager` и освобождает собственный токен PF. Глобальное отключение PF не выполняется: при наличии других ссылок PF продолжает работать. При установке защиты macOS сбрасывает состояния PF, чтобы уже открытые прямые соединения не обходили новые правила; это прерывает существующие соединения, в том числе не относящиеся к приложению.

## Сетевая схема

```text
Приложения → виртуальный адаптер IPv4/IPv6 → sing-box → внутренний SOCKS5 → AWG/Xray → VPN-сервер
Программы с ручной настройкой → прежние локальные SOCKS5/HTTP → тот же AWG/Xray → VPN-сервер
```

- TUN получает адреса `172.31.255.1/30` и `fdfe:dcba:9876::1/126`. Имена интерфейсов приведены в таблице выше. Занятое имя Linux/macOS отклоняется до установки новых защитных правил.
- В sing-box нет прямого исходящего подключения: единственный выход — внутренний SOCKS5. Для Xray в этом режиме разрешается UDP в SOCKS5-входе; TUN обращается непосредственно к нему, минуя публичный TCP-посредник.
- DNS на порту 53 перехватывается; DNS по TCP к `1.1.1.1` проходит через VPN. IPv6 направляется в TUN; если профиль/сервер не поддерживает нужное семейство, прямого запасного выхода нет.
- Адрес VPN-сервера разрешается **до** установки защитных правил и исключается из маршрутов TUN, чтобы избежать петли. Это начальное разрешение имени использует системный DNS. TLS/REALITY serverName сохраняется. При повторе в том же supervisor используется сохранённый адрес; обновление DNS сервера требует нового подключения после снятия блокировки.
- После гибели supervisor при профиле с доменным адресом может потребоваться вручную снять блокировку перед повторным разрешением адреса. Приложение не открывает прямой DNS ради автоматического обхода этой ошибки.
- Правила WFP блокируют прямые исходящие подключения IPv4/IPv6. Исключения: loopback, интерфейс TUN, проверенная защищённая копия сетевого движка и служебные пакеты DHCP/NDP. Входящие подключения извне отдельно не блокируются этой функцией.
- В Linux/macOS исключения ограничены loopback, TUN, служебными DHCP/NDP и точными IP/портами/транспортом VPN-сервера. Исключение VPN-сервера применяется ко всем процессам: пакеты к этому адресу и порту не блокируются фильтром. Прочего разрешения для root-процессов нет. nftables не пропускает `established` в обход проверки интерфейса; обновление цепочки выполняется одной транзакцией. PF использует `no state` для разрешённых соединений и `quick` для окончательного решения.
- Интернет-трафик TCP/UDP передаётся через SOCKS5. Перенос произвольных протоколов IP, включая универсальную поддержку ICMP/ping, не обещается. При невозможности передачи не используется прямой выход.
- Счётчики скорости/байтов пока учитывают только TCP публичных локальных прокси. Трафик TUN в них не включён.

## Процессы и права

`proxy-engine --ipc-admin` остаётся обычным процессом и создаёт локальный именованный канал со случайным именем. Через UAC запускается тот же supervisor с `--ipc-pipe`. Перед пересылкой IPC проверяется повышенный токен клиента канала. Повышенный worker принимает только запуск режима всего трафика. Межпроцессный mutex исключает одновременное управление системным VPN несколькими копиями.

В Linux/macOS используется Unix socket в каталоге `/tmp/apm-vpn-*` с правами `0700`. После авторизации проверяется UID root у подключённого процесса через системные peer credentials. Root-каталог состояния `/var/run/amnezia-proxy-manager` и случайные каталоги сессий доступны только root; блокировка `flock` исключает несколько worker. Компоненты AWG/Xray/TUN копируются с проверкой хешей именно для целевой ОС и правами `0700`. Конфигурация не включается в команды shell/AppleScript.

Linux завершает потомков через `Pdeathsig` и группы процессов. В macOS отдельный наблюдатель читает канал, дескриптор записи которого принадлежит supervisor: авария родителя закрывает канал и завершает группу сетевого процесса. Данные и пути передаются shell-наблюдателю позиционными аргументами, без вставки в исполняемый текст.

Worker копирует AWG/Xray и sing-box в каталог с DACL только для Administrators/SYSTEM, проверяет копии по закреплённым в Go хешам и запускает их из защищённого каталога. Хеши из IPC не дают права запускать произвольный бинарник с повышенными правами. Worker повторно проверяет допустимую схему VLESS, запрещает прямые исходящие подключения, пути к файлам/сертификатам и вложенные сетевые настройки. Конфигурация передаётся через IPC, а временные файлы в режиме VPN защищены той же DACL. Дерево процессов принадлежит Windows Job Object.

Пользовательские переменные окружения XRAY/V2RAY/WIREPROXY/SING_BOX не наследуются повышенными сетевыми процессами; пути TEMP/TMP и рабочий каталог направлены в защищённый каталог. Для sing-box запрашивается штатное завершение через CTRL_BREAK отдельной группы процессов; после тайм-аута применяется Job Object. Гибель процессов не снимает непостоянные, но не привязанные к жизни процесса правила WFP. Обычное закрытие приложения сначала отправляет явную остановку со снятием защиты.

При аварийном завершении защищённый временный каталог в `%SystemRoot%\Temp\amnezia-vpn-*` или `/var/run/amnezia-proxy-manager/session-*` может остаться на диске. Он не доступен обычным процессам пользователя; автоматическая очистка этих аварийных каталогов пока не реализована.

## Проверка и границы результата

Автоматические проверки покрывают сохранение настроек и значение защиты по умолчанию; сохранение защиты при повторе; передачу параметров через IPC; отклонение подменённой копии движка и запрет обычного запуска в повышенном worker; построение маршрутов, TLS serverName, отсутствие прямого выхода и DNS через SOCKS5. Настоящий sing-box проверяет созданный JSON командой `check` без изменения сети:

```powershell
$env:APM_TEST_TUN_BINARY = 'C:\абсолютный\путь\sing-box.exe'
go test ./internal/fullvpn -run TestRealTunConfiguration -v
```

Для Linux в CI добавлен `TestLinuxNftIntegration`: отдельный network namespace, IPv4/IPv6, проверка отбрасывания прямых UDP-пакетов и разрешения loopback/TUN/портов сервера, замена и удаление правил. В macOS добавлен `TestPFNativeSyntax`: настоящий `pfctl -n`, без установки правил и сброса состояний. Обе проверки прошли на нативных runners в [CI 39644353091](https://github.com/Hecatoncheir/amnezia-proxy-manager/actions/runs/39644353091), вместе с тестами и сборками трёх ОС. На Windows также проверены настоящие TAR.GZ, размеры, SHA-256, ELF/Mach-O и лицензии. Полное соединение Unix TUN с реальными профилями этими проверками не подтверждено.

До подтверждения готовности нужны проверки на каждой ОС с настоящими профилями AWG и VLESS:

- [ ] UAC/polkit/macOS: разрешение, отказ, отмена подключения во время запроса.
- [ ] Смена внешнего IPv4/IPv6 для приложения без ручного прокси; SOCKS5 и HTTP одновременно доступны.
- [ ] UDP и DNS через сервер; захват пакетов подтверждает отсутствие прямого выхода DNS/IPv6, включая существующие соединения.
- [ ] Авария AWG/Xray, sing-box, повышенного worker и Flutter; отсутствие прямого интернета в каждой паузе и во время повторов.
- [ ] Проверка штатного удаления адаптера/маршрутов и снятия правил после ручного отключения и выхода.
- [ ] Восстановление кнопкой и CLI, сон/пробуждение, смена Wi-Fi, продление DHCP, IPv6 NDP, перезагрузка.
- [ ] Проверка взаимодействия с другими VPN, защитным ПО и совпадением выбранных подсетей.

Прохождение модульных тестов и `sing-box check` не подтверждает эти сетевые сценарии. Их нельзя считать проверенными в реальной сети на основании сборки.

## Дополнения macOS v0.1.17

DMG-поставка работает вне App Sandbox: загружаемые проверенные движки и привилегированный supervisor запускаются как обычные процессы macOS. Gatekeeper и SIP не отключаются.

После появления `utun233` supervisor создаёт временный системный резолвер `172.31.255.2` для всех доменов через SystemConfiguration Dynamic Store. Это нужно, потому что консольный sing-box не заменяет DNS локального роутера в системном резолвере macOS. Постоянные DNS-настройки сетевых служб не меняются. Ключ принадлежит сессии Dynamic Store и удаляется при штатной остановке или гибели supervisor.

Нативная проверка с текущим профилем, запросом прав администратора, HTTPS без прокси, маршрутом TUN, повторным подключением и снятием защиты:

```sh
cd apps/desktop
flutter build macos --release -t tool/full_vpn_probe.dart
cd ../..
python3 tools/build_supervisor.py --configuration release
codesign --force --deep --preserve-metadata=entitlements,requirements,flags --sign - apps/desktop/build/macos/Build/Products/Release/amnezia_proxy_manager.app
apps/desktop/build/macos/Build/Products/Release/amnezia_proxy_manager.app/Contents/MacOS/amnezia_proxy_manager /tmp/apm-fullvpn-report.json
```

Это отдельная тестовая точка входа. После неё для поставки обязательно выполнить обычную `flutter build macos --release` с основной точкой входа. Профиль остаётся в памяти; JSON-отчёт содержит только результаты проверок.
