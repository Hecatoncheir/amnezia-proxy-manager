# Управление подключением — M3

Круглая кнопка запускает отдельно установленный awg-wireproxy или Xray по
выбранному профилю. AmneziaVPN для работы не нужна. Профиль и ключи остаются
в защищённом хранилище; UI получает только метаданные. Во время сессии смена,
импорт и удаление профилей заблокированы. Повторное нажатие отменяет запуск
либо отключает прокси. Системный прокси и сетевые маршруты ОС не меняются.

## Протокол

Flutter запускает `proxy-engine --ipc` без shell. Канал stdin/stdout — JSON Lines
v1. Первая команда `hello` согласует capabilities `start`, `stop`, `status`, `custom_ports`.
Каждый запрос содержит `version: 1`, строковый `requestId` и `method`.
Ответ содержит тот же requestId и `ok`; ошибки передаются фиксированным `code`.
События имеют `event: state`, `state.status`, `state.connectivity` и безопасный code.

`start` получает family (awg/xray), абсолютный binary, закреплённый SHA-256 и
нормализованную configuration, а также `socksPort` и `httpPort`. Порты должны быть разными целыми числами от 1 до 65535; ошибка `invalid_ports` возвращается до запуска. Старые клиенты без полей портов используют значения supervisor (изначально 1080/8080). Конфиг не передаётся через аргументы процесса.
Лимиты: строка IPC 512 КиБ, конфигурация 64 КиБ, ответ для Flutter 8 КиБ;
ожидание ответа 20 секунд. Таймаут listeners — 8 секунд, HTTPS — 25 секунд.
`start` подтверждает принятие команды сразу, готовность приходит событием.
`stop` ждёт остановки; повторный stop допустим. `status` возвращает состояние.
Версии, неизвестные методы и слишком длинные строки отклоняются.

## Процесс и конфигурация

Перед запуском повторно проверяются бинарник, SHA-256 и Go build info.
Собственные входы — только на `127.0.0.1`, с выбранными на главном экране портами SOCKS5 и HTTP (по умолчанию 1080/8080). Входы из исходного профиля Xray заменяются выбранными локальными портами; HTTPS-проверка использует выбранный SOCKS5-порт.
Проверяются оба занятых порта. Готовность SOCKS5 проверяется рукопожатием,
HTTP — открытием listener; затем отдельный HTTPS-запрос через SOCKS5 с удалённым
разрешением имени и проверкой TLS подтверждает передачу данных.

«Подключено» означает успешную стартовую HTTPS-проверку. «Прокси запущен»
означает готовые локальные входы при ещё проверяемой или неподтверждённой сети.
Это не непрерывный мониторинг VPN или доказательство отсутствия DNS-утечек.
Трафик скорости ещё не измеряется. Прямого сетевого fallback не создаётся.

Конфиг хранится весь срок сессии в отдельном каталоге с DACL владельца/SYSTEM
на Windows либо 0700/0600 на Unix. stdout/stderr backend отбрасываются.
Остановка, EOF интерфейса и закрытие окна завершают процесс и удаляют каталог.
После аварийной гибели supervisor файл может остаться; при следующем старте
убираются только помеченные каталоги без удерживаемой блокировки владельца.
Физическое стирание памяти/диска не гарантируется.

Windows: supervisor входит в Job Object с KILL_ON_JOB_CLOSE. Движок создаётся
приостановленным, назначается в отдельный Job и затем возобновляется; гибель
supervisor закрывает дерево. Unix: отдельная группа, SIGTERM и ограниченное
ожидание, затем SIGKILL. На Linux дополнительно Pdeathsig. SIGKILL supervisor
на macOS требует отдельного решения и нативной проверки.

## Автозапуск и автоподключение

Автозапуск и автоподключение изначально выключены и независимы. Дополнительная настройка «Автозапуск свёрнутым в трей» включает автозапуск и сохраняет признак скрытого старта.

- Автозапуск регистрирует текущий исполняемый файл для текущего пользователя:
  [HKCU Run](https://learn.microsoft.com/en-us/windows/win32/setupapi/run-and-runonce-registry-keys)
  на Windows, [LaunchAgent RunAtLoad](https://developer.apple.com/library/archive/documentation/MacOSX/Conceptual/BPSystemStartup/Chapters/CreatingLaunchdJobs.html)
  на macOS, [XDG autostart](https://specifications.freedesktop.org/autostart/latest/)
  на Linux. Оболочка не используется; пути с пробелами экранируются.
- Автоподключение сохраняется отдельно в настройках. При старте менеджер
  восстанавливает выбранный профиль и выполняет обычное подключение.
  Отсутствующий движок скачивается и проверяется автоматически. Ошибка остаётся видна
  на главном экране; бесконечных повторов подключения нет.

Изменение переключателя автоподключения относится к следующему запуску.
Запись автозапуска подтверждается чтением; ошибка не выдаётся за включённую
настройку. Если автозапуск заблокирован системными настройками Windows,
потребуется разрешить его там. Перемещение переносимого приложения требует
повторной регистрации пути. Фактический вход в систему и деинсталляция
автозапуска ещё требуют платформенных испытаний.

## Проверки Windows

- 100 циклов с реальными дочерними тестовыми процессами, оба формата конфигов;
  после stop освобождены порты и удалены временные каталоги.
- Занятый порт, двойной start, повторный stop, ранняя отмена, неверный хеш,
  аварийный выход движка, EOF и принудительная гибель supervisor.
- Проверка Job Object, отсутствия оставшихся listeners и уборки аварийного файла.
- Настоящий Xray v26.7.28 с обновлённым профилем: HTTPS через SOCKS5,
  stop, повторное подключение. В выбранной старой копии профиль отличался от
  актуального last_config; повторный импорт выбрал актуальную копию без API Premium.
- Настоящий awg-wireproxy v2.1.0 с синтетическим профилем: listeners,
  остановка при закрытии и освобождение портов. Реальная AWG-сеть не проверена.
- Настройки: безопасное значение по умолчанию, сохранение автоподключения,
  подтверждение/ошибка регистрации ОС; Windows registry проверен в изолированном ключе и включением/выключением через UI.
  Автоподключение проверено после hot restart приложения; фактический вход в ОС не проверен.

Нативный сценарий воспроизводится отдельной точкой входа
`tool/session_integration_probe.dart`, включаемой явно. Она читает рабочее
хранилище; если выбрана старая копия с названием AmneziaVPN, повторно импортирует
текущий локальный профиль. Синтетический AWG хранится только в памяти.
Отчёт содержит статусы, без ключей, адресов сервера и содержимого профилей.

## Трей

Записи автозагрузки передают `--autostart`; старые записи без аргумента распознаются и обновляются при включении скрытого старта. Только сочетание аргумента и сохранённой настройки скрывает окно. Обычный запуск ярлыком показывает окно. Значок создаётся через tray_manager; меню позволяет открыть, скрыть или закрыть приложение. Перед выходом останавливается supervisor и удаляется значок.

На Linux дополнительно проверяется `IsStatusNotifierHostRegistered` через пользовательскую шину D-Bus. Наличие одной только шины не считается доступным треем. Если панели нет, окно остаётся видимым. Нативная Windows-проверка подтверждает создание значка, скрытый старт, показ и повторное скрытие; реальные сеансы входа в три ОС ещё требуют проверки.


## Диагностика, восстановление и трафик

Supervisor сохраняет выбранные публичные порты SOCKS5/HTTP за собой на loopback. Движок получает два отдельных динамических loopback-порта. Общий TCP-посредник передаёт байты без разбора содержимого и считает оба направления для AWG и Xray. Никакого прямого сетевого fallback у посредника нет. Соединения ограничены 512 отслеживаемыми сокетами, включая внутренние; остановка закрывает listeners и активные соединения до завершения сессии.

События `state` содержат необязательный объект `traffic: {download, upload}` с накопленными TCP-байтами. Выборка публикуется раз в секунду и при остановке. В объём входят служебные заголовки локального прокси и диагностические запросы; внешний VPN-overhead и трафик вне прокси не учитываются. UI вычисляет скорость по разнице счётчиков и монотонным часам, сохраняет итоговый объём при отключении и сбрасывает его при новом запуске движка.

В `hello` добавлены capabilities `health_check` и `traffic`; метод `check` запрашивает внеочередной HTTPS-тест действующей сессии. Параллельные тесты объединяются. HTTPS через SOCKS5 проверяется после запуска и каждые 30 секунд с таймаутом 25 секунд. Отмена сессии отменяет проверку. Результат старой сессии не должен менять состояние новой.

`RecoveryCubit` хранит намерение оставаться подключённым отдельно от текущего состояния процесса. Авария/потеря IPC/таймаут listener допускают повтор; две последовательные неудачи HTTPS вызывают перезапуск. Пауза растёт на 2 секунды до 30 секунд. Успешная проверка сбрасывает попытки. Ручное отключение и выход отменяют таймер и поздний запуск. Ошибки профиля, доверия и портов не повторяются автоматически. Возвращение приложения в активное состояние запрашивает проверку; смена сети также обнаруживается периодическим тестом, отдельного подписчика на системные сетевые события нет.

`DiagnosticsCubit` последовательно проверяет выбранный профиль через проверенный движок, порты, запуск и HTTPS. Если сессии не было, используется временное подключение с обязательной остановкой; действующая сессия не останавливается. На время диагностики автоматический перезапуск приостановлен, после окончания намерение подключения оценивается заново. Ключи, адреса VPN-сервера и содержимое профиля не входят в результаты.

Автоматические проверки охватывают точный подсчёт байтов, передачу данных без изменений и закрытие сокетов, явный повтор HTTPS, отмену восстановления (включая уже начавшуюся остановку), диагностическую временную сессию, сохранение работающей сессии, занятые порты и ошибку HTTPS. Сон/пробуждение и смена реальных сетей на каждой ОС требуют отдельного нативного прогона.
