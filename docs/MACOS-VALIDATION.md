# Проверка macOS v0.1.17

Дата: 2026-10-22. macOS 27.0.1, Apple Silicon arm64, Xcode 27.1, Flutter 3.47.7, Dart 3.13.5. Исходная AmneziaVPN во время сетевых проверок отключена. Использован действующий выбранный профиль VLESS; конфигурация и ключи в отчёт не включены.

## Исправления

- Обычный запуск больше не остаётся без окна: NIB инициализирует Flutter, затем `window_manager` управляет видимостью. Проверены обычный запуск копии из DMG, скрытый старт, показ/повторное скрытие через трей и развёрнутое состояние.
- DMG работает вне App Sandbox. Ранее sandbox ставил создаваемым движкам карантин `0x86` и запрещал `process-exec`; одного разрешения `user-selected.executable` для внутреннего каталога недостаточно. Установлены и запущены неизменённые AWG v2.1.0, Xray v26.7.28 и sing-box v1.14.3 с проверками SHA-256 и архитектуры. Системные Gatekeeper и SIP не отключались.
- Для полного VPN создан временный системный DNS `172.31.255.2` через SystemConfiguration Dynamic Store. Постоянные настройки сетевых служб не меняются. Ключ принадлежит сессии supervisor; явная остановка удаляет его, гибель процесса закрывает сессию и удаляет ключ автоматически.

## Реальная сеть

`tool/connection_probe.dart`: HTTPS через SOCKS5 подтверждён; HTTPS через HTTP-прокси — 200; счётчики upload/download положительные; остановка и повторное подключение успешны.

`tool/full_vpn_probe.dart`: два цикла полного VLESS VPN с системным запросом прав администратора. Итоговый безопасный отчёт:

```json
{"success":true,"family":"xray","prepared":true,"routeViaTun":true,"httpsWithoutProxy":200,"protectionEnabled":true,"stoppedAndUnblocked":true,"firstConnection":true,"reconnected":true,"internetRestored":true}
```

После завершения `/sbin/route -n get 1.1.1.1` показывает обычный интерфейс `en0`; временный DNS `172.31.255.2` отсутствует в `scutil --dns`. Процессы тестового supervisor и движков завершены.

Первый прогон до исправления DNS поднимал TUN, но HTTPS без прокси завершался по тайм-ауту. После добавления временного системного резолвера тот же сценарий прошёл.

## Границы проверки

Этот прогон не подтверждает реальную AWG-сеть, отсутствие всех DNS/IPv6-утечек, сон/пробуждение, смену Wi-Fi, длительную потерю интернета и автоматический запуск после входа пользователя. Нет доверенной подписи Developer ID/notarization. При первом импорте macOS может запросить доступ к ключам AmneziaVPN; пароль вводится пользователем только в системном окне.


## Дополнительная проверка DNS/IPv6 после v0.1.17

2026-10-22, тот же Mac и выбранный профиль VLESS. Исправление подготовлено для v0.1.18; опубликованная v0.1.17 его не содержит.

Проверен настоящий `proxy-engine --ipc` с правами администратора и установленными Xray/sing-box. Профиль нормализован тем же `ProfileCodec`, передан через stdin; временный файл запроса имел права 0600 и был удалён перед подключением. Исходные конфигурации и захваты с именами сторонних приложений в репозиторий не добавлены.

На физическом `en0` выполнялся отдельный исходящий захват `tcpdump -Q out --immediate-mode` с фильтром `port 53 or port 853 or port 5353 or (ip6 and not icmp6)`. Проверки включали системное разрешение случайного имени общего и корпоративного домена, явные DNS-запросы к роутеру и публичным IPv4/IPv6 DNS, HTTPS с привязкой к `en0`, UDP multicast на `ff02::fb`. После SIGKILL настоящего sing-box проверки повторены с сохранённым PF. DHCP и служебный NDP не считались утечкой пользовательского трафика.

До исправления при выключенной защите:

- захват зафиксировал два исходящих системных DNS-пакета к роутеру;
- HTTPS с привязкой к `en0` завершился успешно, обходя полный VPN.

Причина: фильтр PF устанавливался только при включённой защите при обрыве. Маршруты TUN сами по себе не закрывают локальные подсети и привязку сокета к физическому интерфейсу. Теперь PF действует в течение всего соединения; переключатель управляет сохранением блокировки после отказа. Временный фильтр снимается после завершения процессов, включая ошибки и отмену. Ошибка снятия возвращает `vpn_unblock_failed`, а признак блокировки сохраняется.

Результат после исправления:

| Сценарий | DNS на `en0` | IPv6 на `en0` | Прямой HTTPS через `en0` |
| --- | --- | --- | --- |
| Полный VPN, защита включена | 0 пакетов | 0 пакетов | тайм-аут |
| SIGKILL sing-box, защита включена | 0 пакетов | 0 пакетов | тайм-аут |
| Полный VPN, защита выключена | 0 пакетов | 0 пакетов | тайм-аут |

В обоих работающих соединениях HTTPS без прокси проходит, DNS `172.31.255.2` отвечает, запросы к публичным IPv4/IPv6 DNS проходят через TUN, маршрут к публичному IPv6 указывает `utun233`. Запрос к DNS роутера блокируется. При сохранённой защите после аварии не отвечает ни один проверяемый DNS.

При выключенной защите принудительное завершение sing-box снимает временный PF и восстанавливает обычный DNS автоматически (`unprotectedFailureRestoresInternet: true`). После завершения всего сценария временный DNS и собственный фильтр отсутствуют; системный маршрут снова указывает `en0`.

Контроль без VPN: захват видит обычный DNS и исходящий IPv6 multicast. Это проверяет работоспособность захвата и локального IPv6, а не только отсутствие пакетов во время VPN.

**Ограничения:** до VPN нет внешнего IPv6-маршрута. Полноценная передача внешнего IPv6 через сервер и отсутствие утечек в сети с публичным IPv6 требуют отдельной проверки. Не проверены все физические интерфейсы, смена Wi-Fi, сон, все варианты аварии supervisor/Flutter и реальная AWG-сеть.

Модульные тесты проверяют независимость фильтрации соединения от сохранения блокировки, отсутствие фильтра в режиме локального прокси и передачу ошибки снятия фильтра. `go test ./...`, `go vet ./...` и `go test -race ./internal/session` проходят. Новые методы фильтрации и завершения, а также изменённые небольшие методы имеют CC/COG ≤ 5. Сложность существующего `Manager.run` после выделения завершения снижена с 33/37 до 27/27; его дальнейшее разбиение остаётся отдельным улучшением.

Для повторной ручной проверки с разрешёнными системными запросами, открытым тестовым полным VPN и фактическим именем физического интерфейса:

```sh
sudo tcpdump -n --immediate-mode -Q out -i en0 'port 53 or port 853 or port 5353 or (ip6 and not icmp6)'
# В другом терминале: ответы публичного DNS должны приходить через TUN.
dig @1.1.1.1 example.com A +time=2 +tries=1
dig @2606:4700:4700::1111 example.com AAAA +time=2 +tries=1
# При работающем полном VPN прямое соединение должно завершиться по тайм-ауту.
curl --noproxy '*' --interface en0 --connect-timeout 3 --max-time 5 https://1.1.1.1
```

Повторить при обоих положениях переключателя, затем после остановки только тестового sing-box. С включённой защитой прямые запросы должны оставаться заблокированными; с выключенной — после обработки отказа обычная сеть должна восстановиться. После ручного отключения VPN проверить положительный контроль DNS в захвате. Один тайм-аут IPv6 без работающего IPv6-маршрута не подтверждает отсутствие утечки.
