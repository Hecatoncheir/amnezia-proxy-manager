# Отдельный движок AmneziaWG

## Сценарий

Настоящий backend — [synacker/amnezia-proxy](https://github.com/synacker/amnezia-proxy).
UI и маленький собственный supervisor обновляются из репозитория приложения.
Backend скачивается напрямую из репозитория автора и хранится в каталоге поддержки
приложения: `engines/runtimes/<sha256>/<binary>`, вне установочного каталога UI.
В установщики включён только наш диагностический supervisor `proxy-engine`;
это другой исполняемый файл, не реализация AmneziaWG.

При запуске приложение проверяет запись `engines/active.json`, размер и хеш файла,
архитектуру, поддерживаемую ревизию манифеста и справку CLI. Затем читает GitHub
Releases upstream. Выбирается максимальный совместимый стабильный SemVer,
а не просто `/releases/latest`. Читаются до пяти страниц по 100 выпусков.
При отсутствии движка показывается предложение скачать; загрузка начинается
только по кнопке. При отсутствии совместимых релизов показывается недоступность.
Если сеть недоступна, проверенная локальная копия сохраняет готовность.

## Контракт публикации — предложение для upstream

На 18.10.2026 у upstream **нет тегов, GitHub Releases или этого манифеста**.
Ниже описан реализованный потребителем формат для будущего согласования,
а не описание уже существующих файлов автора.

Стабильный тег `vX.Y.Z` содержит отдельный asset `engine.json` и бинарники:

```json
{
  "schemaVersion": 1,
  "cliContract": 1,
  "sourceRevision": "f5a7912dba8b128ae5c1a3f68a06be7c1668b908",
  "minAppVersion": "0.1.1",
  "maxAppVersionExclusive": "0.2.0",
  "assets": {
    "windows-x64": "awg-proxy-windows-amd64.exe",
    "linux-x64": "awg-proxy-linux-amd64",
    "macos-arm64": "awg-proxy-darwin-arm64"
  }
}
```

Для каждого asset GitHub API должен возвращать `size`, `digest: sha256:...`
и канонический `browser_download_url` этого репозитория и тега. Манифест не более
16 KiB; бинарник не более 128 MiB. Манифест тоже проверяется по размеру и SHA-256.
Текущий UI принимает schemaVersion=1, cliContract=1 и только изученную ревизию.
Новая ревизия требует обновления списка проверенной совместимости приложения;
объявление совместимости самим backend не заменяет эту проверку.

SHA-256 из GitHub API подтверждает целостность относительно опубликованного
автором asset, но не является независимой подписью издателя. Принимаются HTTPS
GitHub/API и серверы release-assets/objects.githubusercontent.com; чужие URL,
неизвестные имена, неподдерживаемая архитектура и перенаправления отклоняются.
Архивы с путями распаковки не используются: скачивается один бинарник.

## Активация

Сначала файл записывается как `<sha256>.part`. После проверки размера/SHA-256,
архитектуры PE x64 / ELF x64 / Mach-O arm64 и успешной справки `-h` он перемещается
в каталог runtime. В Unix выставляется режим 0700. CLI должен поддерживать
`-config`, `-socks-listen`, `-http-listen`, `-dial-timeout`. Проверка запускается
без shell, профиля и соединения с VPN, с лимитом вывода и таймаутом.

Только затем через временный файл переключается `active.json`. Предыдущая запись
сохраняется в `previous.json`. Ошибка загрузки/проверки не активирует кандидата.
Хеш установленного файла проверяется заново при следующем запуске. В M3 supervisor
повторно проверит Go build info: исходную ревизию, отсутствие изменений, ОС/CPU.
Для диагностики это уже доступно командой:

```powershell
cd engine
go run ./cmd/proxy-engine --inspect-backend C:/absolute/path/awg-proxy-windows-amd64.exe --sha256 SHA256
```

`EngineStatus.ready` означает готовность установленного runtime. Это **не состояние
VPN running**: импорт и хранение профиля относятся к M2, управление туннелем к M3.
Кнопка подключения пока отключена. После этих этапов готовность к соединению будет
требовать одновременно совместимый runtime, корректный профиль и готовый supervisor.

## Ограничения текущей подготовки

- Нет настоящего upstream Release, поэтому каталог/загрузка испытаны с контролируемыми
  HTTP-ответами; факт работы GitHub-публикации backend пока подтвердить нельзя.
- Локальный Windows-бинарник проверен реальным CLI и Go build info; Linux/macOS
  пока только кросс-компилированы, установка и исполнение на этих ОС не проверены.
- `tool/engine_install_probe.dart` испытан собранным Windows-приложением с настоящим
  upstream EXE: контролируемый HTTP-каталог → загрузка → хеш/архитектура/CLI →
  активация → повторная проверка runtime. Это не сетевой прогон GitHub Releases.
- Нет запуска туннеля, handshake, проверок DNS/IPv6 или прямого fallback.
- Не реализованы межпроцессная блокировка установки, автоматический откат,
  очистка версий, докачка и замена backend во время работающего туннеля.
- macOS sandbox может запрещать запуск загруженного исполняемого файла. Нативная
  проверка и выбор политики sandbox/подписи обязательны до готовности macOS.
- Право нашего распространения исходников/бинарников upstream не подтверждено.
  Прямое скачивание у автора не добавляет отсутствующую лицензию к исходникам.
