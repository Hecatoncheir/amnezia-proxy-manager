# Отдельный движок AmneziaWG

## Источник и совместимость

Backend — [bropines/awg-wireproxy](https://github.com/bropines/awg-wireproxy).
Проверен [v2.1.0](https://github.com/bropines/awg-wireproxy/releases/tag/v2.1.0),
ревизия `02588433b6328171b594d76f3f16bd3404258a83`. UI и диагностический
supervisor обновляются отдельно. Backend не включается в установщики приложения.

При запуске UI проверяет локальную запись `engines/active.json`, бинарник и CLI,
затем читает до пяти страниц GitHub Releases по 100 записей. Draft/prerelease
пропускаются; выбирается максимальный стабильный SemVer из списка проверенных
совместимых версий. Сейчас в списке только v2.1.0 для UI >=0.1.1 и <0.2.0.
Новые версии автоматически не считаются совместимыми: после проверки разработчик
добавляет версию, ревизию и хеши в `features/engine/engine_release.dart`.

`engine.json` в upstream не нужен. Политика совместимости встроена в приложение;
старый формат для synacker больше не используется. Его локальные записи не принимаются,
но файлы старого движка автоматически не удаляются.

| Платформа UI | Asset автора | Исполняемый файл |
| --- | --- | --- |
| Windows x64 | awg-wireproxy_2.1.0_windows_amd64.zip | wireproxy.exe |
| Linux x64 | awg-wireproxy_2.1.0_linux_amd64.tar.gz | wireproxy |
| macOS arm64 | awg-wireproxy_2.1.0_darwin_arm64.tar.gz | wireproxy |

Windows ARM64 upstream существует, но UI пока не выпускается для этой архитектуры.

## Загрузка и активация

Загрузка начинается по кнопке. Проверяются канонический URL GitHub, размер и SHA-256
из API; SHA-256 также должен совпасть с закреплённой политикой приложения. Разрешены
только HTTPS GitHub/API и серверы release-assets/objects.githubusercontent.com.
Максимальный размер пакета — 128 MiB, распакованного tar — 32 MiB.
Проверенные пакеты имеют размер около 4–5 MiB; их контрольные суммы сверены
с опубликованным `checksums.txt`. Хеш не заменяет подпись издателя.

Установка защищена межпроцессной блокировкой `install.lock`. Пакет сохраняется
как `<archive-sha256>.part`. Из архива в выбранные менеджером пути записываются
только корневой `wireproxy[.exe]` и `LICENSE`; пути остальных записей не используются.
Проверяются размер и отдельный закреплённый SHA-256 бинарника, PE x64/ELF x64/Mach-O
arm64, справка `--help` и точная версия `wireproxy, version 2.1.0`. В Unix бинарнику
задаётся режим 0700. Проверки выполняются без shell и профиля VPN.

Runtime хранится в пользовательском каталоге поддержки приложения:
`engines/runtimes/<archive-sha256>/wireproxy[.exe]`, рядом сохраняется LICENSE.
После всех проверок переключается `active.json`; старая запись — `previous.json`.
При ошибке активная запись не меняется. При повторном запуске проверяются
закреплённый хеш бинарника и CLI. Сетевая ошибка допускает использование
проверенной установленной версии.

В Go доступна независимая диагностика SHA-256 и Go build info: проверяются путь
`github.com/bropines/awg-wireproxy/cmd/wireproxy`, ревизия, `vcs.modified=false`, ОС/CPU.

```powershell
cd engine
go run ./cmd/proxy-engine --inspect-backend C:/absolute/path/wireproxy.exe --sha256 SHA256
```

## Адаптер запуска

Команда — `wireproxy --config ABSOLUTE_GENERATED_CONFIG --silent`, без shell,
daemon и веб-панели. `WIREPROXY_*` исключаются из окружения. Порты SOCKS5/HTTP
передаются через `[Socks5]`/`[http]`; `ProxySections` разрешает только loopback IP
и разные порты 1–65535. `--configtest --config PATH` позволяет проверить профиль
перед будущим запуском M3, не открывая туннель.

M2 обязан сгенерировать конфигурацию из разрешённых полей профиля, исключить
команды, `WGConfig`, секции маршрутизации и другие файловые ссылки upstream,
защитить временный файл и ключи. M3 обязан повторно проверить бинарник и управлять
временем жизни процесса. Эти этапы пока не реализованы.

`EngineStatus.ready` означает установленный проверенный runtime. Кнопка VPN пока
отключена: для подключения нужны M2–M3. Успешный запуск процесса или `/readyz`
без `CheckAlive` не подтверждает сетевую доступность VPN.

## Проверки и оставшаяся работа

На Windows выполнен тест настоящего GitHub API → скачивание ZIP → хеши → CLI →
активация → повторное чтение → готовность без сети → обнаружение повреждения.
Проверены Unicode/пробелы в пути, распаковка ZIP/tar.gz, запрет чужих URL,
непроверенных версий и повреждённых загрузок. Команда воспроизведения:

```powershell
cd apps/desktop
flutter test --dart-define=LIVE_ENGINE=true test/engine_manager_test.dart
```

Остаются нативные macOS/Linux (включая sandbox), внешний сервер и DNS/IPv6,
проверка двух установщиков UI одновременно, явная отмена, докачка,
автоматический откат, очистка версий и обновление работающего туннеля.
