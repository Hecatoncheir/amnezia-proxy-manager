# Профили AmneziaVPN и AmneziaWG

## Импорт

Сначала установите движок через карточку загрузки. В карточке профиля выберите
«Импорт файла» (.conf/.vpn/.json) либо «Ссылка vpn://», задайте название и явно выберите
экспорт. Профили установленной AmneziaVPN читаются только явной кнопкой на Windows;
содержимое буфера обмена автоматически не читается. Поле ссылки скрывает ввод.

Поддерживаются:

- INI .conf: один `[Interface]` и один `[Peer]`, стандартные поля WireGuard и
  параметры AWG, перечисленные в `profile_codec.dart`.
- Текстовый JSON или `vpn://` AmneziaVPN: Base64URL, qCompress (4 байта длины
  big-endian и zlib), `containers` → `amnezia-awg` → `awg.last_config`.
  `last_config` содержит INI `config` либо структурированные клиентские поля.
  Отдельные параметры AWG добавляются к INI; противоречивые значения отклоняются.
- Для старого vpn:// допускается несжатый JSON в Base64URL.

Схема сверена с официальными исходниками AmneziaVPN на ревизии
`ddde43635e957ebf042d92787489da72d3394019`:
[импорт](https://github.com/amnezia-vpn/amnezia-client/blob/ddde43635e957ebf042d92787489da72d3394019/client/core/controllers/selfhosted/importController.cpp),
[экспорт](https://github.com/amnezia-vpn/amnezia-client/blob/ddde43635e957ebf042d92787489da72d3394019/client/core/controllers/selfhosted/exportController.cpp),
[модель AWG](https://github.com/amnezia-vpn/amnezia-client/blob/ddde43635e957ebf042d92787489da72d3394019/client/core/models/protocols/awgProtocolConfig.cpp).
Реальные экспорты пользователя пока не предоставлены; сетевое подключение не проверено.

Дополнительно поддерживаются VLESS через Xray JSON, vless:// и
AmneziaVPN amnezia-xray/last_config. Подробнее: [VLESS и локальный импорт](XRAY.md).

Не поддерживаются остальные VPN-протоколы, API-подписки AmneziaFree/Premium,
административный экспорт без клиентских ключей, QR-изображения/многочастные QR,
резервные копии приложения и несколько Peer. Нужен клиентский экспорт AWG/VLESS либо явный локальный импорт.
DNS должен быть задан явно IP-адресами: системный DNS не подставляется автоматически.

Ограничения: файл/ссылка до 256 КБ, JSON после распаковки до 512 КБ, вложенность
до 32, INI до 64 КБ, до восьми профилей. Объявленная длина qCompress проверяется
до распаковки; результат читается порциями и должен точно совпасть с ней.

## Конфигурация и проверка

Импорт заново строит INI только из разрешённых полей. Проверяются ключи Base64
длиной 32 байта, IP/маски, DNS и endpoint. Запрещены повторяющиеся параметры,
`PostUp/PostDown`, `WGConfig`, подстановка переменных окружения и любые другие
секции upstream, включая правила прямой маршрутизации, прокси и файловые ссылки.
Локальные `[Socks5]`/`[http]` с адресами 127.0.0.1 добавляет сам менеджер.

Перед сохранением и по кнопке «Проверить»:

1. UI повторно проверяет установленный runtime по SHA-256, архитектуре и CLI.
2. Запускает собственный `proxy-engine --validate-config PATH --sha256 HASH`
   без shell. Ключи идут через stdin, в аргументах их нет.
3. Supervisor проверяет SHA-256/Go build info, создаёт защищённый временный
   каталог и файл конфигурации, запускает `wireproxy --config PATH --silent --configtest`.
4. Вывод upstream отбрасывается: его ошибки способны содержать входные ключи.
   Проверка ограничена 12 секундами, внешний UI — 18 секундами. Конфиг удаляется
   после завершения; ошибка очистки означает неуспешную проверку.

В Windows каталог создаётся сразу с защищённой DACL: текущий пользователь и
SYSTEM, наследование этих прав файлам. В Unix каталог 0700 и файл 0600.
При принудительном завершении процесса каталог может остаться с этими правами;
автоматическая уборка после аварии ещё не реализована. Физическое стирание данных
с диска, копий ОС и управляемой памяти Dart не обещается.

`--configtest` проверяет синтаксис и ограничения AWG, но не правильность ключей
на сервере и не доступность VPN. Подключение из UI остаётся этапом M3.

## Хранение и удаление

В состоянии виджетов только случайный ID, заданное пользователем название,
формат и признак временного профиля. Конфигурация и ключи хранятся в закрытой
части контроллера и в системном защищённом хранилище `flutter_secure_storage`:

| ОС | Механизм | Нативная проверка |
| --- | --- | --- |
| Windows | AES-GCM шифрует данные в файле; ключ шифрования хранится в Credential Manager | Пройдена |
| macOS | Keychain без sharing, `usesDataProtectionKeychain: false` | Требуется |
| Linux | libsecret / Secret Service; нужен разблокированный GNOME Keyring или KWallet | Требуется |

В защищённом снимке находятся и конфигурации, и метаданные; plaintext JSON рядом
с приложением или в SharedPreferences не создаётся. Запись подтверждается чтением.
Файловая блокировка и сравнение предыдущего снимка исключают молчаливую перезапись
из другого экземпляра. Это не гарантия атомарности backend хранилища при сбое ОС:
повреждённое или недоступное хранилище не затирается пустым снимком.

При недоступности хранилища предлагается «Только в этом сеансе» либо отмена.
Без явного выбора профиль не добавляется. Временные профили не включаются в
записываемый снимок. Если запись завершилась ошибкой, её исход может быть
неопределённым; интерфейс сообщает об отсутствии подтверждения сохранения.

Удаление требует подтверждения и обновляет защищённый снимок; последний профиль
удаляет запись хранилища. Исходный экспорт пользователя остаётся без изменений.
Системное хранилище не защищает от вредоносного процесса с правами самого пользователя.

## Проверки и разработка

На Windows нативно проверены реальный v2.1.0 configtest, DACL каталога/файла,
сохранение двух синтетических профилей, завершение процесса, восстановление в новом
процессе и удаление. Отдельный ключ `amnezia_m2_native_probe_v1` не затрагивает
пользовательские профили. Воспроизводимый сценарий — `tool/profiles_probe.dart`:
сначала `PROFILE_PROBE_PHASE=write`, затем `read`, выходные JSON задаются
`PROFILE_PROBE_OUTPUT` через `--dart-define`.

Для разработки соберите Flutter и затем `python tools/build_supervisor.py`
из корня проекта: helper должен лежать рядом с приложением. В релизной упаковке
он уже копируется автоматически. После изменения Go-кода пересоберите helper.
Тесты Flutter охватывают опасные директивы, лимиты, повреждения, конфликт записи,
временный режим, импорт/удаление в интерфейсе и узкое окно с крупным текстом.
