# Версии и выпуски

Версия приложения хранится в `apps/desktop/pubspec.yaml`: `X.Y.Z+N`, где N —
номер сборки. Для предварительных выпусков поддерживаются `X.Y.Z-rc.N`,
`X.Y.Z-beta.N`, `X.Y.Z-alpha.N`. Тег должен точно соответствовать версии без `+N`.

## Подготовка

1. Запишите реальные изменения и ограничения в `## Unreleased` файла `Changelog.md`.
2. Из корня репозитория выполните:

```powershell
python tools/release.py prepare v0.1.1
python tools/release.py check v0.1.1
python -m unittest discover -s tools -p 'test_*.py'
```

Команда `prepare` меняет версию, увеличивает номер сборки и переносит Unreleased
в раздел версии с текущей локальной датой. Проверьте изменения перед коммитом.
Для первого выпуска v0.1.0 подготовка уже выполнена, достаточно команды `check`.

3. Закоммитьте готовый код, `pubspec.yaml` и `Changelog.md`, дождитесь зелёного CI.
4. Создайте тег на проверенном коммите и отправьте его:

```powershell
git tag -a v0.1.1 -m "Выпуск v0.1.1"
git push origin HEAD
git push origin v0.1.1
```

## GitHub Actions

`release.yml` запускается только при отправке тега `v*`. Сначала проверяются формат
тега, совпадение версии и единственный непустой раздел changelog. Затем на отдельных
runner выполняются анализ, тесты и сборки Flutter и Go для Windows x64,
macOS arm64 и Linux x64. После успеха всех сборок публикуются три архива,
`SHA256SUMS.txt` и описание из changelog. Предварительные версии отмечаются prerelease
и не становятся Latest. Используется стандартный `GITHUB_TOKEN`; право записи
`contents: write` получает только задача публикации.

Обычный CI проверяет push и pull request. Ошибка сборки блокирует публикацию.
Повторный запуск после успешной публикации не перезаписывает существующий релиз:
`gh release create` завершится ошибкой. Исправления опубликованного кода выпускайте
новой версией, не перемещайте опубликованный тег.

## Установка новой версии

Скачайте архив для своей ОС из GitHub Releases, сравните SHA-256 с `SHA256SUMS.txt`,
закройте приложение и распакуйте новую версию в отдельную папку. Запускайте
`amnezia_proxy_manager.exe`, `amnezia_proxy_manager.app` или `amnezia_proxy_manager`.
На Windows и Linux сохраняйте всё содержимое архива вместе, включая библиотеки
и `data`. В Linux нужны системные GTK 3 и стандартная библиотека C++.

Это переносимые неподписанные сборки, без установщика и автоматического обновления
в интерфейсе. macOS может блокировать запуск неподписанного приложения.
В архив входит диагностический `proxy-engine`, но не upstream backend:
наличие релиза не означает готовность VPN. Работа туннеля и обновление установленной
копии требуют отдельных проверок. Не храните VPN-профили в папке программы.
