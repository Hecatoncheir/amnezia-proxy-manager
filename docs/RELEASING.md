# Версии и выпуски

Версия приложения хранится в `apps/desktop/pubspec.yaml`: `X.Y.Z+N`, где N —
номер сборки. Для предварительных выпусков поддерживаются `X.Y.Z-rc.N`,
`X.Y.Z-beta.N`, `X.Y.Z-alpha.N`. Тег должен точно соответствовать версии без `+N`.

## Подготовка

1. Запишите реальные изменения и ограничения в `## Unreleased` файла `Changelog.md`.
2. Из корня репозитория выполните:

```powershell
python tools/release.py prepare v0.1.2
python tools/release.py check v0.1.2
python -m unittest discover -s tools -p 'test_*.py'
```

Команда `prepare` меняет версию, увеличивает номер сборки и переносит Unreleased
в раздел версии с текущей локальной датой. Проверьте изменения перед коммитом.
Для первого выпуска v0.1.0 подготовка уже выполнена, достаточно команды `check`.

3. Закоммитьте готовый код, `pubspec.yaml` и `Changelog.md`, дождитесь зелёного CI.
4. Создайте тег на проверенном коммите и отправьте его:

```powershell
git tag -a v0.1.2 -m "Выпуск v0.1.2"
git push origin HEAD
git push origin v0.1.2
```

## GitHub Actions

`release.yml` запускается только при отправке тега `v*`. Сначала проверяются формат
тега, совпадение версии и единственный непустой раздел changelog. Затем на отдельных
runner выполняются анализ, тесты и сборки Flutter и Go для Windows x64,
macOS arm64 и Linux x64. После успеха всех сборок публикуются три переносимых архива, Windows Setup, macOS DMG, Linux RUN,
`SHA256SUMS.txt` и описание из changelog. Предварительные версии отмечаются prerelease
и не становятся Latest. Используется стандартный `GITHUB_TOKEN`; право записи
`contents: write` получает только задача публикации.

Обычный CI проверяет push и pull request. Ошибка сборки блокирует публикацию.
Повторный запуск после успешной публикации не перезаписывает существующий релиз:
`gh release create` завершится ошибкой. Исправления опубликованного кода выпускайте
новой версией, не перемещайте опубликованный тег.

## Установка и обновление

Установочные пакеты имеют постоянные имена:

- `AmneziaProxyManager-Setup-windows-x64.exe`: установка без прав администратора
  в `%LOCALAPPDATA%\Programs\AmneziaProxyManager`, ярлыки, удаление через Windows.
  Постоянный AppId позволяет устанавливать новую версию поверх предыдущей.
- `AmneziaProxyManager-macos-arm64.dmg`: перенесите приложение в Applications.
- `AmneziaProxyManager-linux-x64.run`: запустите `sh ./AmneziaProxyManager-linux-x64.run`.
  Программа устанавливается в `~/.local/opt/amnezia-proxy-manager`, создаются команда
  `~/.local/bin/amnezia-proxy-manager` и пункт меню. Root не нужен.

В настройках нажмите «Проверить обновления». Приложение читает публичные GitHub
Releases без токена, выбирает наиболее новую стабильную версию с установщиками
и показывает описание. Проверка выполняется по запросу. Старый v0.1.0 содержит
только архивы и не подходит для загрузки через этот механизм.

«Скачать обновление» загружает пакет подходящей архитектуры в каталог поддержки
приложения, подкаталог `updates`. Отображается прогресс; прерванную загрузку можно
повторить с докачкой. Принимаются только HTTPS-адреса своего GitHub-репозитория
и перенаправления на серверы загрузок GitHub. Перед использованием проверяются
размер и SHA-256 из метаданных GitHub Release Assets. Это проверка целостности,
а не цифровая подпись издателя.

В установленной Windows-копии после загрузки доступна кнопка «Установить и
перезапустить». После подтверждения пакет проверяется повторно, запускается Setup
с параметрами `/VERYSILENT /CLOSEAPPLICATIONS /NORESTART /NORESTARTAPPLICATIONS
/RELAUNCH`, текущим каталогом установки и журналом `updates/install.log`.
Приложение закрывается только после успешного запуска Setup. При ошибке запуска
оно остаётся открытым. Для переносимой копии доступна папка загрузки; Setup
нужно запустить вручную. Каталог установки определяется по расположению
исполняемого файла и наличию `unins000.exe`.

На macOS интерфейс открывает DMG, замену копии в Applications выполняет пользователь.
На Linux интерфейс показывает команду запуска скачанного `.run`; перед её выполнением
нужно закрыть приложение. Полностью автоматическая замена macOS/Linux не реализована.

Для переносимых архивов сохраните всё содержимое вместе, включая библиотеки
и `data`. Linux требует GTK 3 и стандартную библиотеку C++. Пакеты пока не имеют
доверенной подписи издателя или notarization; macOS может ограничивать запуск.
В пакеты входит только диагностический `proxy-engine`, без upstream backend.
Профили и другие пользовательские данные должны храниться вне каталога программы.

## Локальная сборка пакетов

После `flutter build windows --release` и сборки `proxy-engine.exe` в каталог
Flutter Release выполните Inno Setup 6:

```powershell
& "$env:LOCALAPPDATA/Programs/Inno Setup 6/ISCC.exe" /DAppVersion=0.1.1 /DAppNumericVersion=0.1.1 packaging/windows.iss
```

На соответствующих ОС после сборки bundle выполните `bash packaging/build-macos.sh`
или `bash packaging/build-linux.sh`. В macOS `proxy-engine` следует включить в
`amnezia_proxy_manager.app/Contents/MacOS/` перед упаковкой и повторной ad hoc подписью,
как в release workflow. Артефакты записываются в `dist/`.

## Проверка обновления Windows

```powershell
./packaging/check-windows-update.ps1 -Compiler "$env:LOCALAPPDATA/Programs/Inno Setup 6/ISCC.exe"
```

Скрипт проверяет сохранение окна через два отдельных запуска, затем собирает
тестовую старую копию и текущую Release-копию. В отдельном каталоге Temp с отдельным
AppId выполняются настоящая установка, вызов контроллера обновления, замена файлов
и перезапуск. Сверяются хеши EXE и Dart AOT-кода; проверяется сохранение постороннего
файла. Тестовая установка удаляется, журналы остаются в выведенном каталоге Temp.
Этот же сценарий обязателен для Windows в workflow выпуска.

На Linux команда `python3 -m unittest discover -s packaging -p 'test_*.py'`
проверяет извлечение RUN и установку/обновление в изолированном HOME. На Windows
данный тест пропускается; он не подтверждает нативный запуск приложения Linux.
