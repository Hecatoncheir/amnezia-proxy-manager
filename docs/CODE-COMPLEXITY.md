# Простота кода

Состояния интерфейса хранятся в Cubit/Bloc, виджеты показывают готовое состояние и передают действия пользователя. Методы должны решать одну понятную задачу; ранний выход предпочтительнее вложенных условий. Правила для следующих изменений находятся в [AGENTS.md](../AGENTS.md).

## Проверка блока подготовки, 2026-10-18

Использован настоящий [treesitter_cyclomatic_complexity](https://github.com/Hecatoncheir/treesitter_cyclomatic_complexity), ревизия `7b216f2344d87a910e6c1ffbd974fe60950c15ce`, Neovim 0.12.5. Режим `nested_functions = inline`: вложенные замыкания учитываются в родительском методе. Парсер Dart закреплён на ревизии `be07cf7118d3dba06236a3f19541685a68209934` из скрипта установки инструмента.

| Участок | Цикломатическая | Когнитивная |
| --- | ---: | ---: |
| Прежний `_PreparationNotice.build` из тега v0.1.4 | 9 | 22 |
| `PreparationView.build` после переноса состояния | 2 | 2 |
| `PreparationCubit._update` | 4 | 3 |
| `PreparationCubit._engineNotice` | 3 | 2 |
| `PreparationCubit._profileNotice` | 3 | 2 |
| `PreparationCubit.close` | 2 | 1 |

Разделены две задачи: Cubit собирает состояние выбранного движка и профиля, виджет отображает сообщение и индикатор. Используется общий `DownloadRing`; неактивный движок не подменяет прогресс выбранного профиля. Тест проверяет выбор движка и переходы загрузка → установка → готовность.

Это результат для изменённого блока, а не заявление о низкой сложности всех методов приложения. У метрик есть ограничения: например, инструмент не учитывает рекурсивные вызовы. Числа помогают находить сложные места, но не заменяют чтение кода и тесты.

## Как повторить

Установите Neovim и парсер Dart, затем получите указанную ревизию инструмента. Его скрипт `scripts/install-parsers.sh` закрепляет версии грамматик; для Windows можно собрать `src/parser.c` и `src/scanner.c` как DLL в `.ci/parsers/parser/dart.dll`.

Создайте UTF-8 файл `files.txt` с абсолютными путями к проверяемым Dart-файлам, по одному на строку. Из каталога инструмента выполните:

```sh
nvim --clean --headless -l scripts/dump-complexity.lua dart files.txt inline
```

Каждая строка результата содержит путь, номер строки, цикломатическую сложность, когнитивную сложность и название метода. Прежде чем сравнивать результаты, убедитесь, что парсер загружен и список содержит все нужные методы.

## Выбор портов, 2026-10-18

Для новых Dart-классов выбора портов использованы те же инструмент, парсер и режим.

| Метод | Цикломатическая | Когнитивная |
| --- | ---: | ---: |
| `ProxyPorts.parse` | 2 | 1 |
| `ProxyPorts._port` | 4 | 2 |
| `ProxyPortsCubit._load` | 3 | 2 |
| `ProxyPortsCubit.forConnection` | 3 | 2 |
| `ProxyPortsCubit._save` | 5 | 4 |
| `ProxyPortsCubit._write` | 2 | 1 |
| `ProxyPortsView._content` | 5 | 4 |

Проверка номера, сохранение настроек и отображение разделены. Ни один метод новых Dart-классов выбора портов не превышает CC 5 / COG 4. Тесты покрывают границы, совпадение портов, сохранение пары, восстановление и блокировку полей при соединении. Go повторно проверяет параметры до запуска; отдельные тесты открывают и освобождают нестандартные порты для обеих конфигураций.

## Трей и переносимый импорт

Тем же инструментом измерены новые методы трея, Qt INI и общего декодера. Go-парсер закреплён на `2346a3ab1bb3857b48b29d779a1ef9799a248cd7`. До разделения общий `selected` имел CC 14 / COG 24, `decrypt` — CC 13 / COG 12. После разделения чтения, проверки padding, QVariant и выбора контейнера каждый из новых методов имеет CC/COG не выше 5. Новые методы `TrayCubit` и сохранения настройки запуска в трей также укладываются в 5. Старые функции работы с реестром и общим файлом автозагрузки целиком не переписаны и остаются сложнее; это не общий предел для всего проекта.


## Диагностика, восстановление и экран настроек, 2026-10-19

Новые методы `DiagnosticsCubit`, `RecoveryCubit`, `TrafficCubit`, редактора профилей, навигации настроек и TCP-посредника измерены тем же инструментом в режиме `inline`. После разделения сценария на шаги и выделения обработчиков каждый из этих новых методов укладывается в CC/COG 5. Логика выполнения, состояния и отображение разделены; таблица разделов заменяет вложенный выбор виджетов. Методы сетевого наблюдения Go также разделены на наблюдение, выборку и завершение.

Списки файлов и полные результаты локального измерения: `build/m4-dart-files.txt`, `build/m4-go-files.txt`, `build/m4-dart-complexity.tsv`, `build/m4-go-complexity.tsv` (не входят в Git). Общий старый IPC-разбор, запуск процесса и часть главной карточки остаются выше ориентира; утверждение о пределах относится к новым перечисленным компонентам, а не ко всему приложению.
