# VLESS и импорт из установленной AmneziaVPN

Для AmneziaWG используется awg-wireproxy v2.1.0, для VLESS — отдельный
[XTLS/Xray-core v26.7.28](https://github.com/XTLS/Xray-core/releases/tag/v26.7.28).
Движки скачиваются по явному действию; выбор профиля переключает карточку движка.
Runtime Xray хранится в `engines/xray`, отдельно от AWG и установки приложения.

## Доверие к движку

Xray распространяется по MPL-2.0. В приложение не встроены его бинарники.
Сохраняется LICENSE из пакета; исходники доступны в репозитории автора.
SHA-256 трёх архивов сверены с GitHub API, бинарники извлечены и захешированы:
[аудит](backend/xray-release-audit.json), [лицензия](backend/XRAY-LICENSE.txt).
Скрипты, Wintun и geodata из ZIP не устанавливаются.

Выпуск помечен автором как prerelease. Политика разрешает исключительно этот тег
с закреплёнными хешами и диапазоном версии приложения, а не любые prerelease.
На Windows проверены архитектура, `xray version`, SHA-256, Go module/OS/CPU и
`xray run -test`. В опубликованном бинарнике отсутствует `vcs.revision`, поэтому
проверяется закреплённый хеш; sourceRevision фиксирует исходный тег отдельно.
Нативное выполнение на macOS/Linux ещё требует проверки.

## Форматы и нормализация

Поддерживаются Xray JSON, vless:// и AmneziaVPN JSON/vpn:// с
`amnezia-xray → xray.last_config`. Импорт создаёт собственные loopback-входы
SOCKS5 127.0.0.1:1080 и HTTP 127.0.0.1:8080. Исходные входы, routing, DNS,
API и файловые журналы не переносятся. Прямой fallback не создаётся.

Сохраняются VLESS outbounds и цепочки `streamSettings.sockopt.dialerProxy`;
дубли тегов, отсутствующие ссылки и циклы отклоняются. TLS/REALITY и транспортные
поля проходят разрешительный список. Файлы сертификатов, вложенные сетевые
настройки и отключение проверки TLS запрещены. Неизвестные возможности могут
потребовать отдельного адаптера. Проверка синтаксиса не подтверждает соединение.

## Существующий профиль Windows

Кнопка «Из установленной AmneziaVPN» читает только выбранное сохранённое
подключение текущего пользователя. Проверено с AmneziaVPN 5.0.3.0:
QSettings в HKCU, ключ и IV через штатный Credential Manager, AES-256-CBC,
QDataStream QVariant. Нужны доступные текущей учётной записи ключи.
Приложение не запускает AmneziaVPN, не меняет её настройки и не обращается
к API подписки. Новая конфигурация Premium и новый слот не создаются.

В менеджер поступает только клиентский last_config. Ключ подписки, auth_data
и список прочих серверов не копируются. Затем выполняются нормализация,
проверка через движок и сохранение в собственное защищённое хранилище.
Повторный импорт одинакового конфига выбирает существующий профиль.

Сохранённый last_config может устареть: при реальном подключении AmneziaVPN
обновила его. Если синтаксис принят, а сеть недоступна, сначала подключите
AmneziaVPN, повторите импорт и затем отключите её для независимой проверки.
Не запускайте одновременно два клиента с одним профилем без необходимости.

## Диагностика разработчика

`tool/xray_integration_probe.dart` — отдельная явно запускаемая точка входа:
скачивание, реальный импорт и защищённое сохранение, HTTPS через отдельный SOCKS5.
Она использует рабочее хранилище профилей. В приложение при обычном запуске
эта диагностика не включается. Отчёт содержит только статусы и безопасные
категории ошибок. Конфиг передаётся helper через stdin; временный файл защищён
ACL/0600, удаляется после завершения; процесс движка останавливается.

`--probe-xray PATH --sha256 HASH` не меняет системный прокси.
Диагностический HTTPS-запрос использует удалённое разрешение имени через SOCKS5
и обычную проверку сертификата TLS. Постоянное подключение из интерфейса,
IPC, lifecycle и аварийное завершение дерева процессов остаются задачами M3.
