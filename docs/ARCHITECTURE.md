# Архитектура

## Границы

Текущая реализация — UI, отдельная загрузка движка, импорт/системное хранение профилей и однократная проверка через Go CLI/stdin. Управление подключением реализовано через постоянный Go supervisor и JSON Lines IPC; Windows проверена нативно. Схема:

В рабочем коде после v0.1.1 добавлены `features/engine`: проверка каталога upstream
при запуске, подготовка отдельной загрузки и хранение проверенного runtime.
Это не запуск туннеля и не реализация IPC. Правила совместимости и ограничения
описаны в [ENGINE-RUNTIME.md](ENGINE-RUNTIME.md); используется реальный выпуск `bropines/awg-wireproxy` v2.1.0.

```text
Приложение пользователя → SOCKS5/HTTP loopback → upstream awg-wireproxy
                                                   ↓
                                     отдельный AmneziaWG userspace stack
                                                   ↓
                                               VPN-сервер

Flutter UI ← JSON Lines / stdio → Go supervisor → upstream subprocess
```

Upstream реализует сетевой стек; supervisor отвечает за жизненный цикл и безопасный контракт UI. Системный туннель AmneziaVPN и системные proxy settings не изменяются. Обнаружение установки AmneziaVPN — подсказка для экспорта, не разрешение на чтение хранилища.

## Компоненты

Текущий UI разделён на `main.dart`, `features/dashboard/dashboard_page.dart`, `settings/settings_cubit.dart` и `theme/gruvbox.dart`. Один `SettingsCubit<ThemeMode>` управляет темой; `BlocProvider` владеет его жизненным циклом. Простые карточки остаются обычными StatelessWidget, без искусственных событий и репозиториев. Данные сети пока не моделируются фиктивными состояниями.

- Flutter presentation: темы, страницы, состояния. features/profiles реализует импорт и хранилище M2; управление подключением ещё предстоит.
- Dart engine client: планируемый запуск supervisor, JSON framing, таймауты и преобразование событий; бизнес-логика не в виджетах.
- Go supervisor: планируемые IPC, machine state, безопасная передача профиля, управление дочерним процессом.
- internal/upstream: существующий адаптер строит exec.Cmd с абсолютными путями (`--config`, `--silent`), очищает `WIREPROXY_*` из окружения; `ProxySections` создаёт только loopback-секции SOCKS5/HTTP. Профиль для запуска должен быть сгенерирован менеджером после строгого разбора M2. Он не проверяет происхождение binary, не читает профиль и не запускает процесс.
- internal/upstream.VerifyBinary: отдельная проверка SHA-256 и Go build info
  загруженного backend; доступна через `proxy-engine --inspect-backend`, пока не
  связана с запуском туннеля. Вызывающий код M3 обязан выполнить её перед start.
- features/profiles: строгий разбор экспортов, закрытые записи с ключами, безопасные ProfileSummary для виджетов и системное хранилище; подробности в [PROFILES.md](PROFILES.md).
- internal/validation: однократный --validate-config; чтение stdin, защищённый временный файл, ограниченный configtest без вывода upstream и очистка.

Не вводить сервис с повышенными привилегиями без доказанной необходимости.

## Контракт IPC

Реализованный JSON Lines v1: hello/capabilities, start, stop, status и события state.
Профиль передаётся в stdin с лимитом 64 КиБ; stdout/stderr движка не возвращаются.
Предел строки 512 КиБ, ответа UI 8 КиБ, ответы привязаны к requestId.
Полный контракт и безопасные коды: [SESSION.md](SESSION.md).

## Состояния

disconnected → starting → running → stopping → disconnected; ошибка из starting/running ведёт в error с закрытием ресурсов. Повторный stop идемпотентен. start во время starting/running отклоняется. События старого поколения процесса игнорируются. running означает готовые listeners; отдельно отражать проверку сети/handshake, не подменять её фактом запуска процесса.

Закрытие UI/EOF завершает supervisor и backend. На Windows реализованы Job Objects; на Unix — группы процессов, мягкое завершение и ограниченный timeout перед принудительным. exec.CommandContext в текущем адаптере сам по себе не решает завершение дерева.

## Профили и безопасность

Импорт — осознанное действие пользователя. Не обходить ACL, Keychain, DPAPI или закрытые форматы. Наличие файла не означает совместимость. Парсер должен ограничивать размер, проверять ключи/адреса и не исполнять wg-quick hook-команды. Нельзя логировать ключи и vpn://.

Только loopback listeners. LAN-доступ потребовал бы отдельной модели аутентификации и сейчас не поддерживается. Локальные процессы всё равно могут использовать loopback-прокси — это не граница изоляции пользователей. Не обещать системный kill switch. DNS клиента может утечь до прокси: необходимо удалённое разрешение имени и реальные проверки. При отказе VPN запрещён прямой fallback.

## ОС и поставка

| ОС | Каркас | До beta |
| --- | --- | --- |
| Windows | Flutter runner, Go CLI | Job Object, Credential Manager/DPAPI, installer и подпись |
| macOS | Flutter runner с исходными sandbox entitlements | Проверка subprocess, Keychain, network entitlements, notarization |
| Linux | GTK runner, Go CLI | Secret Service, отсутствие keyring, пакет и зависимости |

В v0.1.1 в macOS добавлен network.client для проверки/загрузки обновлений,
но sandbox оставлен включённым. Возможность запуска скачанного backend внутри
этого sandbox ещё не подтверждена. Наличие runner не доказывает работоспособность
туннеля на ОС. CI собирает UI нативно; backend проверяется отдельно.

## Решение об интеграции

Выбран процессный адаптер, поскольку upstream публикует самостоятельный CLI `cmd/wireproxy`; процессная граница позволяет использовать готовые архивы автора. Он позволяет явно контролировать версию и отделить UI. Лицензия ISC и Windows-бинарник проверены; полная опись уведомлений зависимостей и нативные проверки остальных ОС остаются в M1. Возможный последующий fork с библиотечным API требует отдельного решения и тестов.

## Ограничения конфигурации awg-wireproxy

Порты задаются в `[Socks5]` и `[http]`, а не флагами CLI. Веб-панель, daemon,
SNI, входящие туннели и правила маршрутизации upstream не включаются менеджером.
В импорте M2 разрешены только необходимые поля `[Interface]`/`[Peer]`:
исходный файл upstream не передавать напрямую. `WGConfig`, файловые ссылки,
пользовательские секции и команды запрещены. В частности, whitelist-маршрутизация
upstream способна направить несовпавший домен напрямую; приложение её не использует.
`/readyz` без `CheckAlive` возвращает 200 без подтверждения туннеля: это не сигнал VPN ready.


## Дополнение: второй движок VLESS

Поддержан отдельный Xray v26.7.28 с закреплёнными архивами и бинарниками,
собственным каталогом runtime и проверкой через Go helper. AWG сохраняет
прежний каталог и политику. Профиль выбирает требуемый движок; скачивание
остаётся явным действием. Импорт из установленной AmneziaVPN на Windows
использует штатное хранилище текущего пользователя и переносит только
клиентскую конфигурацию, без данных подписки. [Подробности](XRAY.md).


## Реализация M3

ConnectionCubit управляет SupervisorClient и блокировкой профиля; StartupCubit
хранит автоподключение и согласует автозапуск с ОС. Go session реализует IPC,
проверку runtime, процессы, готовность и cleanup. [Протокол и проверки](SESSION.md).
