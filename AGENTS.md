# Правила разработки

- Общаться и писать пояснения на русском языке.
- Управлять состоянием интерфейса через `flutter_bloc`: простые состояния — `Cubit`, поток событий с отдельными обработчиками — `Bloc`. Виджеты показывают состояние и передают действия пользователя.
- Писать небольшие методы с одной понятной задачей. Использовать ясные названия, ранний выход и простую последовательность шагов.
- Избегать вложенных тернарных выражений, глубоких условий, скрытых побочных действий и лишних прослоек. Не усложнять код ради формального уменьшения числа строк.
- При изменении сложного участка измерять цикломатическую и когнитивную сложность через `Hecatoncheir/treesitter_cyclomatic_complexity`. Стремиться к значениям не выше 5 для каждого метода; превышения сначала пытаться упростить. Это ориентир для изменяемого кода, а не утверждение о состоянии всего репозитория.
- Не удалять проверки ключей, конфигураций, хешей и процессов ради уменьшения метрик. Сохранять тесты значимого поведения и проверять ошибки и отмену.
- Всегда предусматривать вертикальные отступы между группами элементов интерфейса: обычно 8–12 пикселей внутри группы и 16–24 пикселя между группами. Кнопки не должны прилегать к разделителям, заголовкам или следующим блокам. Проверять отступы также при раскрытии секций, появлении ошибок и переносе кнопок на несколько строк.
